#! Abstract

Limited-stock product launches, ticket releases and festival discount events share one uncomfortable property: a very large number of buyers arrive within the same few seconds and compete for a small, fixed number of units. A conventional e-commerce checkout, in which every request locks and updates an inventory row in a relational database, degrades badly under this pattern. Requests queue on a single hot row, response times climb, buyers retry, and the retries deepen the queue. Worse, when the system is under this stress it is also most likely to sell the same unit twice.

This project designs, implements and measures a **High-Concurrency Flash Sale Platform**: a backend reservation service that admits purchase attempts for a single sale at in-memory speed while keeping a relational database as the durable record of truth. The system is built with Java 25 and Spring Boot 4, PostgreSQL 16, Redis 7 and Apache Kafka. An atomic Redis Lua script acts as the admission gate, checking remaining stock, the per-user limit and an idempotency key in one indivisible step and issuing a short-lived hold. Accepted claims are persisted together with a transactional outbox row, relayed to Kafka, and fulfilled asynchronously by an order worker that charges the buyer's saved payment method and creates the order idempotently. A reconciler expires abandoned holds and continuously verifies the stock invariant.

The work is evaluated by driving one million purchase attempts from a k6 load generator against a sale of one thousand units, first through a baseline path that performs all work inside the request transaction, then through the optimised path. The comparison reports throughput, latency percentiles, and the oversell count, which must be zero in both cases. The report also presents the low-level design, the database schema, a full trace of the claim feature through the MVC layers, and a production deployment design on AWS using Elastic Beanstalk, RDS, ElastiCache and MSK inside a private VPC.

The techniques demonstrated apply directly to ticketing, limited-edition retail, seat and slot booking, and any system where correctness under a burst matters more than average-case throughput.
